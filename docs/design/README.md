# Backbit Design Foundations

## Purpose

This document defines the first product-facing design rules for Backbit. The goal is to keep the project cinematic, editorial, and focused, while avoiding generic SaaS aesthetics.

## Design direction

Backbit should feel like a game diary with the tone of a magazine cover and the clarity of a modern interface. The experience should be calm, sharp, and intentional, with strong hierarchy and enough personality to feel like a product, not a template.

## Typography

### Serif display
Use a cinematic serif for titles, section headers, big stats, quotes, and hero statements.

Recommended traits:
- High contrast.
- Editorial feel.
- Elegant but readable at large sizes.
- Slightly dramatic without looking luxury-brand cliché.

### Sans-serif UI
Use a minimal sans-serif for interface labels, buttons, forms, navigation, metadata, and system text.

Recommended traits:
- Clean and neutral.
- Excellent readability on mobile.
- Modern but not sterile.
- Works well in compact UI and dense data views.

## Type pairing

The serif should carry emotion and identity.
The sans-serif should carry structure and usability.

The product should never look like both fonts are fighting for attention.

## Visual tone

Backbit should avoid common startup combinations that feel overused.
Instead of defaulting to the usual clean blue-violet tech look, the visual language should lean toward a more atmospheric, filmic, and collectible tone.

The interface should feel:
- Editorial.
- Slightly dark or mood-driven.
- Premium but not flashy.
- Productive, not decorative.
- Distinct from generic AI or dashboard aesthetics.

## Layout principles

- Mobile-first.
- Strong spacing rhythm.
- Clear hierarchy.
- Large touch targets.
- Compact metadata sections.
- Frictionless switching between discover, board, and profile.

## Content principles

Copy should sound human, direct, and product-led.
Avoid generic startup phrases, empty superlatives, and AI-flavored wording.
Use short statements that explain value quickly.

## Voice for landing page

The landing page should communicate three things fast:
- What Backbit does.
- Why it is different.
- Why it feels worth using every day.

The pitch should focus on the backlog problem, the discovery problem, and the feeling of finally having a game tracker that helps with decisions instead of just storage.
